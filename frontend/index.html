IxNetwork Session Explorer

Unified dashboard for tracking IxNetwork sessions across all chassis in your lab

Quick Start

  1. 01
    Add an IxNetwork server

    Click Manage Servers in the top-right header, then Add Server. Enter the server's name, host / IP, username, and password. REST port defaults to 443 (IxNetwork Web) or 11009 (IxNetwork Classic). Use Test Connection to verify credentials before saving.

  2. 02
    Wait for the first poll

    After saving, the backend polls the server automatically within the configured interval (default 60 s). The LIVE indicator in the header confirms real-time polling. Click Refresh in the toolbar to force an immediate poll.

  3. 03
    Explore your sessions

    Each IxNetwork server appears as a collapsible block. Click the block header to expand it and see all active sessions. The Active counter in the stats bar shows how many sessions have control-plane or data-plane activity.

Server Blocks

Each block represents one IxNetwork server. Click the header row to collapse or expand its session list.

Session Table — Column Reference

SESSION

Session name assigned by the IxNetwork user. Below the name: a state badge (Active / Initial / Stopped) and any amber tags you've applied.

CHASSIS

Physical chassis hostname and port location that the virtual port is mapped to. LLDP neighbor info (connected switch / port) is shown below in smaller text when available.

PORT

IxNetwork virtual port name plus a link-state dot. = link up, = link down.

CP

Control Plane. ✓ means at least one protocol engine (BGP, OSPF, ISIS, etc.) has active device groups on this session's ports. The session is actively running protocol emulation.

DP

Data Plane. ✓ means traffic is actively flowing through the physical ports (non-zero frame counters). Requires IxOS chassis integration.

UTILIZED

Logical OR of CP and DP. A session is utilized if it is doing anything meaningful — running protocols or passing traffic. Non-utilized sessions may be safe to clean up.

Session Actions

Details
Expands an inline sub-table showing per-vport details: chassis slot, IP, link state, LLDP neighbor switch and port. Click again to collapse.
Tag
Attach one or more comma-separated labels to a session (e.g. bgp, owner:ashwin, lab-a). Tags are persisted in the database and survive poll cycles. Use them to track ownership or test purpose.
Logs
Download a diagnostic log bundle for the session. Available only when the server is reachable.
Kill
Irreversible. Permanently terminates the IxNetwork session and releases all reserved ports. A confirmation modal always appears before execution.

Search & Filter

The search box in the control bar filters all visible sessions in real time — no page reload required.

Session name
Type any part of the session name to narrow results
Chassis
Filter by chassis hostname or IP (e.g. lab-01)
Tag
Filter by a tag you've applied (e.g. bgp or owner:ashwin)

Sessions on collapsed server blocks are also filtered — expand to see them.

Poll & Auto-Refresh

Refresh
Triggers an immediate backend poll of all servers and refreshes the UI. The progress bar in the button shows poll completion.
Auto-refresh: OFF
Toggles a 30-second client-side UI refresh. Keeps the page current without you clicking Refresh manually. The dot turns green when active.
Poll: 60s
Click the gear button to change how often the backend polls IxNetwork servers. Range: 10–3600 s. Persisted in the database.

Polling runs server-side regardless of browser state. Close the tab and data will still be collected.

Color & Status Legend

Cyan

Interactive elements — buttons, links, active column headers, focused inputs. Cyan = something you can act on.

Green

Active / healthy state — session with CP or DP active, server reachable, link up, UTILIZED = YES, Active stat counter.

Amber

Degraded / informational — session in Initial state, link down, server with auth warning, and all applied session tags.

Crimson

Error / danger — unreachable server, session errors, the Kill action, and any destructive confirmation dialogs.

Managing Servers

Add Server
Open Manage Servers → Add Server. Name and host are required. REST port defaults to 443.
Bulk Import
Paste multiple servers as CSV lines:
name,host,username,password[,rest_port]
Edit / Delete
Each server row has edit (pencil) and delete (trash) icons. Deleting removes it from future polls but does not touch the actual IxNetwork server.
Bulk password
Select multiple servers via checkboxes, then click Update Password to set a new credential for all selected at once.

Tips & Shortcuts

  • Expand / Collapse All buttons in the toolbar let you quickly see or hide all session tables at once.
  • Tags survive backend polls — stored in local SQLite, not on the IxNetwork server.
  • Use owner:name tag conventions to track who owns a session across a shared lab.
  • LLDP neighbor data in chassis cells shows which switch port a test port is cabled to.
  • A pulsing crimson error badge on a session row means IxNetwork reported app errors — click to read them.
  • The API is available at /docs (Swagger UI) for programmatic access or scripting.
